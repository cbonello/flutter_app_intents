# Android Configuration

## Recommended: Use Code Generator

**✨ NEW in v0.8.0**: The easiest way to set up Android App Actions is using the code generator:

```bash
# 1. Define intents in Dart with AppIntentBuilder
# 2. Run the generator
dart run flutter_app_intents:app_intents_cli --platform=android

# 3. That's it! The generated shortcuts.xml is automatically included in your build
```

**Optional: Install globally**
```bash
dart pub global activate flutter_app_intents
app_intents_cli --platform=android
```

The generator creates `android/app/src/main/res/xml/shortcuts.xml` with all App Actions configured and automatically integrated into your Android build.

### What Gets Generated

The code generator creates:
- `shortcuts.xml` with Google Assistant integration
- Built-in Intent (BII) mappings based on intent category
- Proper capability declarations for voice commands
- Parameter mappings for BII requirements
- Automatic main activity detection

### Example Generated Code

```xml
<?xml version="1.0" encoding="utf-8"?>
<!-- AUTO-GENERATED by flutter_app_intents:generate -->
<!-- DO NOT EDIT MANUALLY -->
<shortcuts xmlns:android="http://schemas.android.com/apk/res/android">

  <capability android:name="actions.intent.START_EXERCISE">
    <intent
      android:targetPackage="com.example.myapp"
      android:targetClass="com.example.myapp.MainActivity">
      <parameter
        android:name="exercise.name"
        android:key="exercise_type"/>
      <parameter
        android:name="exercise.duration"
        android:key="duration"/>
    </intent>
  </capability>

</shortcuts>
```

## Requirements

### Minimum SDK Version

Android App Actions require:
- **Minimum SDK**: Android 6.0 (API level 23) or higher
- **Recommended**: Android 10.0 (API level 29) or higher for best compatibility

Set this in `android/app/build.gradle`:

```gradle
android {
    defaultConfig {
        minSdkVersion 23  // Minimum for App Actions
        targetSdkVersion 34
    }
}
```

### Google Play Services

No additional Google Play Services dependencies are required. App Actions work through the Google Assistant app, which is pre-installed on most Android devices.

## AndroidManifest.xml Configuration

### Automatic Configuration

The generator automatically detects your main activity from `AndroidManifest.xml`. No manual changes are typically needed.

### Custom Main Activity

If your app uses a custom main activity (not `MainActivity`), specify it when generating:

```bash
dart run flutter_app_intents:app_intents_cli --platform=android --main-activity=SplashActivity
```

### Verify shortcuts.xml Reference

The generator creates the file, but you should verify your `AndroidManifest.xml` includes the reference:

```xml
<application>
    <activity android:name=".MainActivity">
        <!-- App Actions shortcuts reference -->
        <meta-data
            android:name="android.app.shortcuts"
            android:resource="@xml/shortcuts" />

        <intent-filter>
            <action android:name="android.intent.action.MAIN"/>
            <category android:name="android.intent.category.LAUNCHER"/>
        </intent-filter>
    </activity>
</application>
```

## Testing App Actions

### Local Development Testing (ADB)

**⭐ Recommended for local development:** ADB is the standard way to test Android App Actions during development.

```bash
# Test your intents using deep links
adb shell am start -a android.intent.action.VIEW -d "app://intent/<your_intent_identifier>"

# Example: Test increment_counter intent
adb shell am start -a android.intent.action.VIEW -d "app://intent/increment_counter"

# If the app is already running, you'll see:
# "Warning: Activity not started, intent has been delivered to currently running top-most instance."
# This is NORMAL and means the intent was successfully delivered!

# To test from a fresh start:
adb shell am force-stop com.example.your_app
adb shell am start -a android.intent.action.VIEW -d "app://intent/increment_counter"
```

**Why use ADB for testing?**
- ✅ Works immediately without additional setup
- ✅ Tests the same code paths as voice commands
- ✅ No need to publish the app
- ✅ Fast iteration during development

### Testing with Google Assistant (Production)

**Important:** Google Assistant voice commands **do NOT work for unpublished apps** during local development. Voice commands require one of:

1. **App published on Google Play** (including internal testing track)
2. **Google Assistant Plugin** for Android Studio (see below)
3. **App Actions Console** registration

**Voice commands will work after publishing:**

**Fitness Intent:**
```
"Hey Google, start workout in MyApp"
"Hey Google, start running using MyApp"
```

**Messaging Intent:**
```
"Hey Google, send a message with MyApp"
"Hey Google, message John using MyApp"
```

**Navigation Intent:**
```
"Hey Google, get directions in MyApp"
"Hey Google, navigate to home with MyApp"
```

### Google Assistant Plugin for Android Studio

To test voice commands during development, use the Google Assistant Plugin:

1. **Install the plugin:**
   - File → Settings → Plugins → Search "Google Assistant"
   - Install and restart Android Studio

2. **Open App Actions Test Tool:**
   - Tools → App Actions Test Tool
   - Or View → Tool Windows → App Actions Test Tool

3. **Configure your app:**
   - Select your app from the dropdown
   - The tool will read your `shortcuts.xml` automatically

4. **Test intents:**
   - Type voice commands in the test interface
   - Preview what Google Assistant would return
   - Test different parameters and variations

**Benefits:**
- Test voice commands without publishing
- Preview Google Assistant responses
- Debug parameter passing
- Validate BII mappings

### Static Shortcuts (App Launcher)

Your shortcuts will also appear when users **long-press your app icon** in the launcher menu. This works immediately without any additional setup.

### Publishing for Production Voice Commands

To enable real Google Assistant voice commands:

1. **Build release APK:**
   ```bash
   flutter build apk --release
   ```

2. **Upload to Google Play Console:**
   - Create an app in Google Play Console
   - Upload to Internal Testing track (or higher)

3. **Register in Actions Console** (optional but recommended):
   - Visit [Google Actions Console](https://console.actions.google.com/)
   - Create a new project
   - Link to your Google Play app
   - Upload your `shortcuts.xml`

4. **Wait for indexing:**
   - Google takes ~10-60 minutes to index your app
   - Install from Play Store on your test device
   - Voice commands will now work!

### Testing Checklist

**Local Development:**
- ✅ Test with ADB commands
- ✅ Verify intents are delivered (`onNewIntent` called)
- ✅ Check Flutter handlers execute correctly
- ✅ Test with app running and app closed
- ✅ Verify parameters are passed correctly

**Before Publishing:**
- ✅ Test with Google Assistant Plugin
- ✅ Verify voice command phrasing is natural
- ✅ Check all BII parameters map correctly
- ✅ Test edge cases (missing parameters, etc.)

**After Publishing:**
- ✅ Install from Play Store
- ✅ Test real voice commands with Google Assistant
- ✅ Verify shortcuts appear in launcher long-press menu
- ✅ Check Google Assistant search results

## Built-in Intent (BII) Mappings

The code generator automatically maps your intent categories to Google's Built-in Intents:

| Intent Category | BII Action | Example Voice Command |
|----------------|-----------|---------------------|
| fitness | `actions.intent.START_EXERCISE` | "Start workout" |
| messaging | `actions.intent.SEND_MESSAGE` | "Send message" |
| music | `actions.intent.PLAY_MUSIC` | "Play music" |
| navigation | `actions.intent.GET_DIRECTIONS` | "Get directions" |
| calling | `actions.intent.CALL_CONTACT` | "Call contact" |
| general | `actions.intent.OPEN_APP_FEATURE` | "Open feature" |

### Category-Specific Parameters

The generator also maps parameters correctly for each BII:

**Fitness (START_EXERCISE):**
- `exercise_type` → `exercise.name`
- `duration` → `exercise.duration`

**Messaging (SEND_MESSAGE):**
- `recipient` → `message.recipient`
- `message_text` → `message.text`

**Music (PLAY_MUSIC):**
- `song_name` → `music.song`
- `artist` → `music.artist`

## Main Activity Customization

### Why Customize?

You may need to specify a custom main activity if:
- You use a splash screen activity
- You have multiple activities and need to specify which handles intents
- Your main activity has a custom name

### How to Customize

Use the `--main-activity` flag:

```bash
# For a splash screen
dart run flutter_app_intents:app_intents_cli --main-activity=SplashActivity

# For a custom launcher
dart run flutter_app_intents:app_intents_cli --main-activity=LauncherActivity
```

The generator will use this activity in the `shortcuts.xml`:

```xml
<intent
  android:targetPackage="com.example.myapp"
  android:targetClass="com.example.myapp.SplashActivity">
  <!-- ... -->
</intent>
```

## Manual Setup (Alternative)

**⚠️ Note**: Manual setup is only needed if you're not using the code generator or need advanced customization.

### 1. Create shortcuts.xml

Create `android/app/src/main/res/xml/shortcuts.xml` manually:

```xml
<?xml version="1.0" encoding="utf-8"?>
<shortcuts xmlns:android="http://schemas.android.com/apk/res/android">

  <capability android:name="actions.intent.OPEN_APP_FEATURE">
    <intent
      android:targetPackage="com.example.myapp"
      android:targetClass="com.example.myapp.MainActivity">
      <parameter
        android:name="feature"
        android:key="feature_name"/>
    </intent>
  </capability>

</shortcuts>
```

### 2. Add to AndroidManifest.xml

Reference the shortcuts file in your manifest:

```xml
<activity android:name=".MainActivity">
    <meta-data
        android:name="android.app.shortcuts"
        android:resource="@xml/shortcuts" />
</activity>
```

### 3. Handle Intent Parameters

In your Dart code, handle the intent parameters:

```dart
final intent = AppIntentBuilder()
    .identifier('open_feature')
    .title('Open Feature')
    .description('Opens a specific app feature')
    .category(IntentCategory.general)
    .parameter(const AppIntentParameter(
      name: 'feature_name',
      title: 'Feature Name',
      type: AppIntentParameterType.string,
    ))
    .build();

await client.registerIntent(intent, (parameters) async {
  final featureName = parameters['feature_name'] as String?;
  // Handle the feature navigation
  return AppIntentResult.successful(value: 'Opening $featureName');
});
```

## Troubleshooting

### Shortcuts Not Appearing in Google Assistant

1. **Verify shortcuts.xml exists**: Check `android/app/src/main/res/xml/shortcuts.xml`
2. **Rebuild the app**: Run `flutter clean && flutter build apk`
3. **Check AndroidManifest.xml**: Ensure `android.app.shortcuts` meta-data is present
4. **Clear Google app data**: Settings → Apps → Google → Storage → Clear Cache
5. **Reinstall the app**: Uninstall and reinstall to refresh Assistant integration

### Voice Commands Not Recognized

1. **Check BII mapping**: Ensure your category matches the voice command type
2. **Use correct phrasing**: Match Google's expected voice patterns for each BII
3. **Test with ADB**: Verify the intent works before testing voice
4. **Check Google Assistant language**: Must match your app's supported languages

### Invalid shortcuts.xml Errors

1. **Regenerate with code generator**: `dart run flutter_app_intents:app_intents_cli --platform=android`
2. **Validate XML syntax**: Check for missing closing tags or invalid characters
3. **Check package name**: Ensure `targetPackage` matches your app's package in `build.gradle`
4. **Verify parameter mappings**: BII parameters must use correct Google-defined names

### Hot Restart Required

After regenerating `shortcuts.xml`, you must use **hot restart** (not hot reload):
- Press `R` (capital R) in Flutter terminal
- Or run `flutter run` again

**Why Hot Restart vs Hot Reload?**

- **Hot reload** (`r`) - Only updates Dart code, fast but limited to Flutter framework
- **Hot restart** (`R`) - Restarts entire app including native platform resources

`shortcuts.xml` is a **native Android XML resource**, not Dart code. Android loads these resources when the app starts, so they require a full app restart to be recognized by Google Assistant.

**What happens with hot reload only:**
- ❌ Google Assistant won't recognize new or updated shortcuts
- ❌ Changes to BII mappings won't take effect
- ❌ Parameter updates won't be reflected
- ✅ Only a hot restart will reload the native Android resources

### Testing on Emulator

Google Assistant may not work properly on some emulators:
1. **Use a real device** for best testing experience
2. **Enable Google Play** on emulator if using AVD
3. **Sign in to Google account** on emulator
4. **Install latest Google app** from Play Store

### Parameter Type Mismatches

If you get BII validation errors:
1. **Check generator warnings**: The generator shows parameter type mismatches
2. **Use correct parameter names**: Each BII has required parameter names
3. **Match parameter types**: String, integer, boolean must match BII requirements
4. **Regenerate after fixes**: Run generator again after correcting intent definitions

## Best Practices

### 1. Use Appropriate Categories

Choose the category that best matches your intent's purpose:
- ✅ **fitness** for workout/exercise features
- ✅ **messaging** for sending messages
- ✅ **navigation** for maps and directions
- ✅ **general** for custom features not matching specific BIIs

### 2. Provide Required Parameters

Each BII has required parameters. The code generator validates and warns you:

```dart
// ✅ CORRECT - includes required parameter for messaging
final intent = AppIntentBuilder()
    .identifier('send_message')
    .title('Send Message')
    .category(IntentCategory.messaging)
    .parameter(const AppIntentParameter(
      name: 'recipient',  // Required for SEND_MESSAGE BII
      title: 'Recipient',
      type: AppIntentParameterType.string,
    ))
    .build();
```

### 3. Test Thoroughly

- Test with real voice commands, not just ADB
- Test on multiple Android versions
- Test with different Google Assistant languages
- Use the App Actions Test Tool in Android Studio

### 4. Use Watch Mode During Development

Enable watch mode for rapid iteration:

```bash
dart run flutter_app_intents:app_intents_cli --watch
```

The generator will automatically regenerate `shortcuts.xml` when you change your Dart intent definitions.
