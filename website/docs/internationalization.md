# Internationalization (i18n)

The flutter_app_intents package supports internationalization with different levels of support for iOS and Android platforms.

## Overview

Internationalization allows your app to support multiple languages for:
- Intent titles and descriptions
- Siri voice phrases (iOS)
- Widget text (Android)
- Google Assistant commands (Android)

## Android Internationalization ✅

Android has **full i18n support** through the standard Android localization mechanism.

### Widget Strings

The code generator automatically creates string resources for Android widgets in `android/app/src/main/res/values/strings.xml`:

```xml
<!-- Auto-generated by flutter_app_intents -->
<resources>
    <!-- Widget: get_weather -->
    <string name="widget_get_weather_description">Get current weather information</string>
    <string name="widget_get_weather_loading">Loading weather...</string>
</resources>
```

### Adding Translations

To support multiple languages, create locale-specific `strings.xml` files:

**1. Create locale directories:**
```
android/app/src/main/res/
├── values/strings.xml          # English (default)
├── values-es/strings.xml       # Spanish
├── values-fr/strings.xml       # French
├── values-de/strings.xml       # German
└── values-ja/strings.xml       # Japanese
```

**2. Add translations:**

**`values-es/strings.xml`** (Spanish):
```xml
<?xml version="1.0" encoding="utf-8"?>
<resources>
    <!-- Widget: get_weather -->
    <string name="widget_get_weather_description">Obtener información del clima actual</string>
    <string name="widget_get_weather_loading">Cargando el clima...</string>
</resources>
```

**`values-fr/strings.xml`** (French):
```xml
<?xml version="1.0" encoding="utf-8"?>
<resources>
    <!-- Widget: get_weather -->
    <string name="widget_get_weather_description">Obtenir les informations météo actuelles</string>
    <string name="widget_get_weather_loading">Chargement de la météo...</string>
</resources>
```

### Shortcut Labels

App Shortcut labels in `shortcuts.xml` are currently hardcoded. To internationalize them:

**1. Move labels to string resources:**

**`values/strings.xml`:**
```xml
<resources>
    <string name="shortcut_get_weather_label">Get Weather</string>
    <string name="shortcut_send_message_label">Send Message</string>
</resources>
```

**2. Update `shortcuts.xml` to reference them:**
```xml
<capability android:name="actions.intent.OPEN_APP_FEATURE">
    <intent android:targetPackage="com.example.myapp"
            android:targetClass="com.example.myapp.MainActivity">
        <parameter android:name="feature"
                  android:key="@string/shortcut_get_weather_label"/>
    </intent>
</capability>
```

**3. Add translations in locale-specific files:**

**`values-es/strings.xml`:**
```xml
<resources>
    <string name="shortcut_get_weather_label">Obtener Clima</string>
    <string name="shortcut_send_message_label">Enviar Mensaje</string>
</resources>
```

### How Android Selects Language

Android automatically selects the appropriate language based on:
1. User's device language settings
2. Fallback to default (`values/strings.xml`) if no matching locale

## iOS Internationalization ⚠️

iOS has **partial i18n support**. Some aspects are automatically localized, while others require manual setup.

### What's Already Localized

**Intent Titles** use `LocalizedStringResource`, which automatically supports `.strings` files:

```swift
// Generated by flutter_app_intents
static var title: LocalizedStringResource = "Increment Counter"
```

This automatically looks for translations in `Localizable.strings`.

### Siri Phrases (Manual Setup Required)

Siri phrases are currently generated in English and hardcoded:

```swift
// Generated code (English only)
phrases: [
    "Increment Counter with MyApp",
    "Increment Counter in MyApp",
    "Increment Counter using MyApp"
]
```

**To internationalize Siri phrases:**

**1. Create `Localizable.strings` files:**

**Base localization** (`en.lproj/Localizable.strings`):
```
"intent.increment_counter.phrase1" = "Increment Counter with %@";
"intent.increment_counter.phrase2" = "Increment Counter in %@";
"intent.increment_counter.phrase3" = "Increment Counter using %@";
```

**Spanish** (`es.lproj/Localizable.strings`):
```
"intent.increment_counter.phrase1" = "Incrementar Contador con %@";
"intent.increment_counter.phrase2" = "Incrementar Contador en %@";
"intent.increment_counter.phrase3" = "Incrementar Contador usando %@";
```

**French** (`fr.lproj/Localizable.strings`):
```
"intent.increment_counter.phrase1" = "Incrémenter le Compteur avec %@";
"intent.increment_counter.phrase2" = "Incrémenter le Compteur dans %@";
"intent.increment_counter.phrase3" = "Incrémenter le Compteur en utilisant %@";
```

**2. Manually update generated `AppShortcuts.swift`:**

```swift
// Manual modification needed
phrases: [
    .init(stringLiteral: NSLocalizedString("intent.increment_counter.phrase1", comment: "")),
    .init(stringLiteral: NSLocalizedString("intent.increment_counter.phrase2", comment: "")),
    .init(stringLiteral: NSLocalizedString("intent.increment_counter.phrase3", comment: ""))
]
```

**⚠️ Important Limitation:**
- Siri phrases **cannot be dynamically generated** at runtime
- Must be static at compile time for iOS speech recognition
- After regenerating with the CLI, you'll need to manually update the phrases again

### How iOS Selects Language

iOS automatically selects based on:
1. User's preferred language in Settings
2. System language
3. Fallback to base localization (English)

## Best Practices

### General Guidelines

1. **Keep Dart definitions in English** - Use English as the canonical source for code generation
2. **Add translations after generation** - Don't translate Dart code; translate the generated platform files
3. **Test in multiple languages** - Verify that voice commands work in each supported language
4. **Document supported languages** - Let users know which languages your app supports

### Android-Specific

1. **Use standard locale codes** - Follow Android's locale naming (e.g., `values-es`, `values-fr`, `values-pt-rBR`)
2. **Provide fallback strings** - Always have complete translations in `values/strings.xml`
3. **Test widget rendering** - Verify text doesn't overflow in different languages
4. **Keep widget text concise** - Short text works better across languages

### iOS-Specific

1. **Create all `.lproj` directories** in Xcode for proper localization support
2. **Test Siri recognition** - Different languages may have different recognition patterns
3. **Keep phrases natural** - Work with native speakers to ensure phrases sound natural
4. **Limit phrase count** - 3-5 phrases per intent is optimal for recognition quality

## Current Limitations

### Android
- ✅ **Widget text**: Fully supported via string resources
- ⚠️ **Shortcut labels**: Requires manual string resource setup
- ✅ **App names**: Automatically localized by Android

### iOS
- ✅ **Intent titles**: Automatically supported via LocalizedStringResource
- ❌ **Siri phrases**: Requires manual Localizable.strings setup and code modification
- ⚠️ **Generated code**: Regeneration requires re-applying manual translations

## Testing Internationalization

### Android

**1. Change device language:**
```
Settings → System → Languages & input → Languages → Add language
```

**2. Test with ADB:**
```bash
# Change locale temporarily
adb shell setprop persist.sys.locale es-ES
adb shell stop
adb shell start

# Reset to English
adb shell setprop persist.sys.locale en-US
adb shell stop
adb shell start
```

**3. Verify widget text:**
- Add widget to home screen
- Check that text appears in correct language
- Verify no text overflow issues

### iOS

**1. Change Siri language:**
```
Settings → Siri & Search → Language → [Select language]
```

**2. Test voice commands:**
```
"Hey Siri, [translated phrase]"
```

**3. Verify in Shortcuts app:**
- Open Shortcuts app
- Check that intent titles appear in correct language
- Test shortcuts work in selected language

## Common Issues

### Android

**Problem:** Widget shows default English text even though translation exists

**Solution:**
1. Verify locale code format (e.g., `values-es` not `values-spanish`)
2. Check string resource names match exactly
3. Clean and rebuild: `flutter clean && flutter build apk`
4. Restart device to reload resources

**Problem:** Shortcut labels not translated

**Solution:**
- Move labels to string resources
- Update `shortcuts.xml` to reference `@string/resource_name`
- Add translations to all locale-specific `strings.xml` files

### iOS

**Problem:** Siri doesn't recognize translated phrases

**Solution:**
1. Verify Siri language matches `.lproj` directory
2. Ensure phrases are natural in target language
3. Test with simpler, shorter phrases
4. Check iOS Shortcuts app shows translated text
5. Restart device to reload Siri index

**Problem:** Translations lost after regeneration

**Solution:**
- This is expected behavior - manual modifications to generated files are overwritten
- Keep translations in separate `.strings` files
- Document which phrases need manual updating
- Consider creating a post-generation script to reapply translations
